# Forge public v1: Armor 3.0 data model

## Scope

This version is static and public. It has no Bungie login, backend, secret, live account read, client-side Bungie API request, Armor 2.0 logic, or machine-learning recommendation layer.

Build content is committed as JSON. The browser loads that JSON and applies deterministic filters.

## Current sandbox baseline

The seed catalogue is labelled for the Monument of Triumph sandbox and checked against Bungie material through Update 9.7.0.3 dated July 7, 2026.

Destiny 2 is not expected to receive planned live-service content after Update 9.7.0, although Bungie may still issue health or stability hotfixes. Every content update must therefore check the latest patch notes before changing `verified` to `true`.

## Armor 3.0 rules represented

Only these six stats are valid:

- Weapons
- Health
- Class
- Grenade
- Super
- Melee

Each stat target is an integer from 0 to 200.

Armor records may also specify:

- preferred three-stat archetypes
- minimum gear tier from 1 to 5
- two-piece and four-piece set bonus names
- notes explaining why a set bonus is omitted
- a verification flag for the Armor 3.0 recommendation

The schema does not permit legacy stat names.

## Current archetype catalogue

The original six archetypes:

| Archetype | Primary | Secondary |
|---|---|---|
| Paragon | Super | Melee |
| Grenadier | Grenade | Super |
| Specialist | Class | Weapons |
| Brawler | Melee | Health |
| Bulwark | Health | Class |
| Gunner | Weapons | Grenade |

Six archetypes added in Update 9.7.0:

| Archetype | Primary | Secondary |
|---|---|---|
| Siegebreaker | Health | Grenade |
| Skirmisher | Melee | Weapons |
| Demolitionist | Grenade | Class |
| Colossus | Super | Health |
| Reaver | Class | Melee |
| Powerhouse | Weapons | Super |

Every Armor 3.0 item has a primary, secondary and tertiary stat. The tertiary stat is selected from the remaining stats.

## Gear tiers

The model accepts tiers 1 to 5. Tier 4 and Tier 5 armor can provide additional mod-energy behaviour, and Tier 5 armor has a tuned stat. Exact item rolls are not generated by this static catalogue.

## Set bonuses

A build may list set bonuses, but the seed records deliberately leave them empty where the current exact set and perk text has not been checked. Armor 3.0 set bonuses activate at two and four matching pieces. There is no five-piece bonus requirement.

## Build record structure

Each build contains:

- stable ID and display name
- class and subclass
- activity and difficulty tags
- roles and summary
- Exotic armor and reason
- Armor 3.0 stat targets, archetypes, tier and set bonuses
- subclass abilities, aspects and fragments
- slot-by-slot armor mods
- Artifact dependencies
- weapon requirements and examples
- gameplay loop
- source notes
- record-level and section-level verification flags
- human-review notes

The canonical schema is:

`/astrix-app/data/armor-3-build.schema.json`

The seed catalogue is:

`/astrix-app/data/armor-3-builds.json`

## Verification policy

`verified: true` means the exact statement was checked against a current source.

`verified: false` means at least one detail still needs human confirmation. The UI must show this clearly. It must not silently present an unverified record as current meta.

A record remains false when any important child section is false.

## Deterministic selection rules

The rules layer is `/astrix-app/build-rules.js`.

Selection order is inspectable:

1. Exclude malformed records.
2. Match selected subclass when one is supplied.
3. Match selected activity tag when one is supplied.
4. Sort verified records before unverified records.
5. Sort exact activity matches before broad matches.
6. Use build name as the stable final tie-breaker.

There is no AI scoring, hidden weighting, remote request or personalized inference.

## Static-update pattern

Seasonal or hotfix maintenance means editing JSON and source notes, not changing rendering code. A future GitHub Action may generate or validate static JSON, but the deployed page must still read committed files. No secret may be exposed to the frontend.
