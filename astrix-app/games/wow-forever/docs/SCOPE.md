# The Caster (WoW Forever build advisor): scope

Status: foundation only. No live pages, no account linking, no recommendations yet.
Written 3 Oct 2026. Facts about WoW Forever are as published on that date and are sourced at the bottom.

## Why this vertical

WoW Forever launches on 4 Nov 2026. It is a permanent level 60 Classic-era mode included in the normal WoW subscription. The first three raids (Barrow Deeps, Hyjal Summit, Onyxia's Lair) unlock on 9 Dec 2026, which is when demand for gear and upgrade help peaks.

The tool space filled up fast during beta, but every existing tool is a planner or a database:

- around ten talent calculators
- wow-forever.gg: talent and Legacy calculators, item database, BiS lists with stat weights, downrank calculator, raid roster, profession planner, browser-only build saver
- a simulator addon still in development

None of them advise. None take what a player owns and explain, with sources, what to change next and why. That is the ASTRIX PARADOX difference, and it carries over directly.

## Product rules (same as Destiny, unchanged)

1. Advisor, not planner. Filled-in recommendations, every claim traced to a source and explained.
2. Synergy is a directed chain: A's output feeds B's input. "Both good" is never a synergy.
3. No invented data. Every value comes from the pinned client build or an official Blizzard post. Anything unconfirmed shows an honest pending state.
4. Inventory-aware. Advice starts from the player's own gear and talents, not theorycraft.
5. Counter-reasoning is the same engine pointed at the encounter.
6. Pages load in 3 to 4 seconds. Users never struggle with the UI.

## v1 scope (API independent, can start now)

In:

- Character setup: class, race, level, faction, ruleset.
- Talents: the three class trees, including the new 16-point milestone, with rules validation (points, rows, prerequisites).
- Legacy trees: account-wide points across three trees, with the published 16-point cap.
- Gear: manual slot-by-slot entry with item search over the Forever item database, set bonus tracking and stat totals.
- Stat model for Forever's changes: single hit and crit stats, bonus healing that includes one third of bonus damage, reduced weapon skill per item.
- Advisor: weak points, conflicts, cause-and-effect synergies, upgrade path from owned gear by content phase (dungeons now, raids from 9 Dec).
- Healer mana efficiency using downrank data.
- Build review page on its own URL. Save, duplicate and share via URL.

Out of v1:

- Battle.net account linking. Blizzard has not published Forever profile API namespaces. The adapter is designed but blocked until they exist.
- Automatic gear import. A later optional route is a small out-of-combat addon that writes an export string, like the SimulationCraft export.
- DPS simulation. We explain cause and effect, we do not sim.

## Data model

All game data is generated by the pipeline in `../pipeline/` from client DB2 tables, pinned to one Forever client build. Schemas live in `../schema/`. Rule values the client tables do not hold (Legacy cap and trees) live in `../data/rules.json`, each with an official source.

| Entity | Source tables | Notes |
| --- | --- | --- |
| Item | ItemSparse, Item | name, quality, item level, required level, slot, class/subclass, stats, set id |
| Item set | ItemSet, ItemSetSpell | pieces, bonus thresholds, bonus spell ids |
| Spell | Spell, SpellName, SpellEffect, SpellLevels | name, rank, effects, levels, used for talents, procs, set bonuses |
| Talent tree | TalentTab | class, order, name, background |
| Talent | Talent | tree, row, column, ranks (spell id per rank), prerequisites |
| Legacy talent | not in client tables yet | pending until Blizzard publishes or the build ships it |
| Character build | user data | class, race, level, talents, legacy points, gear |

Every generated record carries a provenance block: product, build, source table, row id and the sha256 of the source CSV. A record with a field the pipeline could not resolve keeps that field as `{ "pending": true, "reason": "..." }`. Nothing is filled with a guess.

## Platform mapping

The game module translates Forever concepts into the generic ASTRIX PARADOX contract (`astrix-app/platform/contracts/game-module.mjs`). No WoW ids or terms go into platform code.

| Forever concept | Platform concept |
| --- | --- |
| Item (weapon, armour, trinket) | Equipment |
| Class spell, active talent | Ability |
| Passive talent, Legacy perk, set bonus, item proc | Passive modifier |
| Boss mechanic, resistance check, raid buff slot | Encounter requirement |
| Character | Character |
| Battle.net profile (later) | Player identity source |

## Sources of data

- Client DB2 exports from wago.tools, product `wow_classic_beta` while Forever is in beta. The build is pinned in `../pipeline/forever-sources.json` and only changed by a reviewed PR.
- Official Blizzard posts for anything not in the client (Legacy trees, respec cost, dual spec cost).
- Never: Wowhead scraping, QuestieDB (no permission from its maintainers), or Retail and Classic Era namespaces swapped in for Forever data.

## Hard restrictions

- Never reverse-engineer Battle.net auth, reuse session tokens or scrape logged-in Blizzard services.
- No game memory reading, traffic interception or automation of in-game actions.
- No implied Blizzard endorsement. Check Blizzard's fan content terms before using any artwork.
- Miguel does every login. Builds end with a manual QA checklist.

## Known unknowns (pending until confirmed)

- Total talent points at 60 and points per level.
- Dual spec cost and switching rules. Launch respec cost.
- Legacy perk ranks and costs. The three tree names and the 16-point cap per character are sourced in `data/rules.json`.
- Final launch client build number.

## Milestone (2 to 4 weeks)

1. Week 1 (done, build 1.60.1.70094): 9 classes, 27 talent trees, 432 talents, 536 item sets, 8,043 equippable items. Headers locked. Item stat amounts stay pending: this build stores stat allocations, and the client formula that turns them into amounts is not verified yet.
2. Week 2 (done in `engine/build-rules.mjs`): talent ownership, rank and prerequisite checks, Legacy cap, stat totals by raw stat id. Row unlock and total points stay pending until sourced.
3. Week 3: advisor v0: weak points, conflicts and first cause-and-effect chains, every claim citing its record.
4. Week 4: build the pages from the approved wireframes (published as the "The Caster Wireframes" artifact, kept out of the repo so no unfinished page goes live) into the ASTRIX tool shell. Re-pin to the launch build after 4 Nov.
